# Как работает система (для руководителя)

## Как устроена система

Система состоит из двух частей: сайта, которым пользуются сотрудники, и базы данных, где хранятся объекты, задачи и их история. Сайт — это только «окно» в базу. Все правила доступа записаны в самой базе, а не на сайте.

Есть две роли. **Постановщик** создаёт объекты (стройки) и задачи, назначает исполнителей, принимает работу или возвращает её на доработку с комментарием. **Исполнитель** видит только свои задачи, берёт их в работу и отправляет на проверку.

Каждая задача проходит по фиксированному маршруту: «Новая» → «В работе» → «На проверке» → «Принята» или «На доработке» → снова «В работе». Каждый шаг автоматически записывается в историю задачи: кто, когда, из какого статуса в какой и с каким комментарием.

## Как защищены данные

Главный принцип: **база данных сама проверяет каждое действие**. Даже если человек разбирается в программировании и попробует отправить запрос в обход сайта, база выполнит его только в рамках его прав. Скрытая кнопка на сайте ничего не решает: решает база.

Регистрация закрыта, пользователей добавляет только администратор. Без входа в систему данные недоступны вообще. Служебный ключ, который даёт полный доступ к базе, хранится только у администратора и не попадает на сайт.

## Чего не может исполнитель (даже в обход сайта)

- увидеть чужие задачи и объекты, где у него нет задач;
- создать, отредактировать или удалить задачу;
- принять свою работу сам или перескочить через этап проверки;
- изменить, удалить или подделать историю задачи.

Постановщик тоже не может нарушить порядок: статус меняется только по разрешённому маршруту, а вернуть задачу на доработку без комментария нельзя.
